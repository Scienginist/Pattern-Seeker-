# CatalystFlow 설계 메모

## 1. 기존 자산 평가

이 저장소에는 README 한 줄 외에 **이전 앱의 코드도 운영 데이터도 없었다**. 그래서 재사용할 수 있는 저장·원장·계보 코드가 없어 새로 설계했다.
이전 앱의 데이터 파일 위치가 확인되면 다음 순서로 가져오기를 추가한다.

1. 원본은 읽기 전용으로 연다.
2. 복사본으로 변환한다.
3. 검증한 뒤 사용자 확인을 받고 들여온다.

원본은 절대 수정하지 않는다. 지금도 새 앱은 별도 데이터 폴더(`%LOCALAPPDATA%\CatalystFlow`)만 쓴다.

## 2. 구조

```
catalystflow/
  schema.py    테이블 정의, 필수 QC 목록
  db.py        저장 계층: 연결, 트랜잭션, 복사본 이전, 백업·복원(무결성 검사)
  services.py  업무 규칙: 모든 쓰기 = @command (한 트랜잭션 + op_id 멱등)
  server.py    127.0.0.1 전용 HTTP. 실행마다 무작위 토큰 필요. 화면과 규칙을 잇기만 함
  app.py       실행·창(pywebview), 단일 실행 잠금, 하루 1회 자동 백업
  web/         화면(바닐라 JS, 외부 라이브러리·CDN 없음)
```

- **트랜잭션**: 분할·병합·소비·정정·취소는 모두 `BEGIN IMMEDIATE … COMMIT`으로 처리한다. 하나라도 막히면 전체를 롤백한다.
- **중복 방지**: 화면이 폼마다 op_id를 만들어 초안과 함께 보관한다. 같은 op_id가 다시 오면 서버는 처음 결과만 돌려준다. 더블클릭, 응답 유실 뒤 재시도, 앱을 재시작한 뒤 재시도 모두에 해당한다.
- **충돌 방지**: 편집 가능한 행에는 `version`이 있다. 오래 열린 창에서 저장하면 409로 막고 "최신 내용으로 다시 열기"를 안내한다.
- **이력**: `audit_log`에 수정 전·후 JSON, 사유, op_id를 남긴다. 취소도 행을 지우지 않고 취소 표시로 남긴다.

## 3. 데이터 관계

| 개념 | 테이블 | 핵심 |
|---|---|---|
| 원료 Lot | `raw_lots` + `raw_ledger` | 잔량 = 입고 + Σ(투입·정정). 원료는 `charge_raw`에서만 차감 |
| 배치 / 가지 | `batches`, `branches` | 가지 = 생산·연구·예외. 공통 조건은 배치에, 가지별로 달라진 조건은 가지에 둔다 |
| 공정(계획+실행) | `steps`, `step_events` | 계획→진행→보류→완료. 시각이 NULL이면 미기록. 다음 공정은 자동으로 시작하지 않는다 |
| 물질 단위 | `materials` | 질량 + 종류(실측/추정/계산/계획/미측정) + 기준(슬러리 전체/습윤/건조/그대로) |
| 계보 | `step_io` | 공정별 in(전량/일부) · out · through(제자리 처리). 여러 입력·출력을 가지는 그래프 |
| 가지 이동 | `material_moves` | 물질 정체성은 그대로 두고 소속만 바꾼다(새 소분이 아님) |
| 제품 재고 | `products`(material_id UNIQUE) + `product_usages` | 이중 입고 방지. 재처리 사용은 새 물질과 계보로 연결 |
| QC | `qc_items`, `qc_decisions` | 계획·의뢰·수령, 의뢰일·회신 예상일·측정일, 결과 요약, 파일 경로, 대표성. 사용자가 판정 |
| 초안 | `drafts` | 키 = `배치|가지|공정|동작`. 실제 기록과 완전히 분리 |

### 질량 규칙
- 소분 잔량은 원본이 실측·계산값일 때만 계산값으로 낸다. 원본이 추정값이면 잔량도 추정으로 남고 확정 재고로 보지 않는다. 미측정이면 계산하지 않는다.
- 단순 병합은 같은 기준의 확정 투입 합을 넘는 산출을 막고, 산출을 비우면 합계를 계산값으로 넣는다.
- 반응·세척·건조 같은 공정은 질량 보존을 강제하지 않는다.
- 사용자가 선택하지 않은 물질은 어떤 공정에도 들어가지 않는다.

### QC 규칙
- 제품을 등록하면 필수 6종(XRD·BET·과전압·pH·TGA·XRF)이 생기고 PSA는 선택으로 추가할 수 있다. 과전압·pH는 내부 측정이라 측정 예정일을 직접 잡는다.
- 합격은 필수 6종이 모두 "결과 수령"이고 각 결과의 대표성을 "대표함"으로 확인해야 선택할 수 있다. 앱이 자동으로 판정하지 않는다.
- 분리·병합·재처리로 생긴 새 산물에는 결과를 승계하지 않는다. 계보상 이전 결과를 보여주고, 사용자가 근거를 적어 "대표 결과로 인정"하면 연결한다. 원래 결과는 보존된다.

### 정정 경로
| 상황 | 경로 |
|---|---|
| 잘못 넣은 투입 | `연결 정정`에서 해당 물질만 제외 → 물질 상태·질량 복원 |
| 빠진 투입·산출 | `연결 정정`에서 추가 |
| 후속 공정·제품·QC가 걸린 산출 | 무엇이 막는지 목록으로 안내. 조건·메모 수정은 허용 |
| 잘못 입력한 공정 전체 | `기록 취소`(물질 복원, 원료 투입 취소) |
| 실제로 원료를 되돌려놓음 | `실물 반환`(투입 기록 유지 + 반환 원장) |
| 중복 입고 Lot | 투입 Lot 변경 → 휴지통. 사용 이력이 있으면 삭제를 막고 해당 배치·공정을 안내 |

E2E 과정에서 실제 버그 다섯 개를 찾아 고쳤다.
- 숨겨진 모달이 모든 클릭을 가로챘다.
- 저장 뒤에도 선택이 남아 있었다.
- 선택 바가 저장 버튼을 가렸다.
- 패널이 닫힐 때 늦게 온 `change` 이벤트가 삭제된 초안을 되살렸다.
- "최신 내용으로 다시 열기"에서 이전 초안이 되살아났다.

## 5. 아직 확인하지 못한 것 / 다음 단계

- **Windows 실기 실행 미확인.** 이 환경은 Linux라서 PyInstaller 빌드와 실행은 Linux에서만 확인했다(번들된 화면 제공, 데이터 폴더 분리). Windows exe는 `.github/workflows/catalystflow-windows.yml`에서 테스트, 빌드, 스모크 테스트를 거친다. 실제 PC에서 WebView2 창과 창 닫기 시 초안 저장은 확인이 필요하다.
- 백업과 복원 경로는 텍스트로 입력한다. 파일 선택 대화상자는 아직 없다.
- 출하 일정(보조 기능)은 제품 사용 기록의 날짜로만 다룬다.
- 이전 앱 데이터 가져오기는 원본 위치를 알게 되면 위 1절의 순서로 추가한다.
